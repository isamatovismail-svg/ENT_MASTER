# План развития ENT MASTER

Работать по этапам, по порядку. После каждого этапа: все тесты (`python -m unittest`) проходят,
новые функции покрыты тестами, README обновлён, сделан git-коммит с понятным сообщением.

Жёсткие ограничения проекта (из CLAUDE.md) действуют для всех этапов:
- только стандартная библиотека Python 3.11+, HTML и CSS;
- без JavaScript (CSP запрещает скрипты), без фреймворков и сторонних пакетов;
- база данных остаётся **SQLite**, PostgreSQL не используем;
- интерфейс и комментарии на русском (вопросы по казахскому языку и литературе — на казахском,
  по иностранному языку — на английском).

Секреты (пароли, ключи) хранить только в `.env`, никогда в коде и в git.

## Этап 1. Чистка проекта и ввод телефона

1. Найти и удалить неиспользуемые файлы, функции, импорты, шаблоны и CSS-классы.
   Перед удалением убедиться поиском по проекту, что это действительно нигде не используется.
   Список удалённого перечислить в сообщении коммита.
2. Ввод телефона в любом виде: `8 705 967 84 20`, `+7 (705) 967-84-20`, `87059678420`,
   `77059678420`, `7059678420` → нормализовать в `+77059678420`. Пробелы, скобки, дефисы
   убирать. Понятная ошибка, если цифр не 10 после кода страны. Использовать везде,
   где вводится телефон (регистрация, вход, админка).
3. Защита ручных правок вопросов: если админ изменил вопрос (в том числе сгенерированный),
   пометить его (колонка `edited_by_admin`) — `seed.py` такие вопросы больше не перезаписывает.

## Этап 2. Регистрация с подтверждением почты и вход через Google

Регистрация — два способа, телефон вводится по желанию и **не** подтверждается:

**А. Почта + код.**
1. Форма: имя, фамилия, почта, телефон (необязательно), пароль и повтор.
2. Аккаунт создаётся неактивным; на почту приходит 6-значный код (действует 15 минут,
   не более 5 попыток ввода, в базе хранится только хеш кода).
3. Страница ввода кода; после верного кода аккаунт активен и пользователь входит.
4. «Отправить код ещё раз» — не чаще раза в минуту.
5. Восстановление пароля: «Забыли пароль?» → код на почту → новый пароль.
6. Отправка писем через `smtplib` (SMTP Gmail, порт 465, SSL). Настройки в `.env`:
   `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD` (пароль приложения Gmail),
   `MAIL_FROM`. Если SMTP не настроен — в режиме разработки код печатается в консоль.
7. В тестах письма не отправлять — подменять отправитель (как FakeAPI у бота).

**Б. «Войти через Google» (OAuth 2.0, Authorization Code Flow).**
1. Сейчас кнопка неактивна с подписью «скоро» — сделать рабочей.
2. Только `urllib`: редирект на Google с `state` (защита от подделки), обмен `code` на токен
   на `https://oauth2.googleapis.com/token`, данные пользователя — из `id_token`
   (проверить `aud`, `iss`, `exp`) или запросом userinfo.
3. Почта от Google считается подтверждённой. Если пользователь с такой почтой уже есть —
   войти в его аккаунт, иначе создать новый (имя и фамилию взять из Google).
4. Настройки в `.env`: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`
   (для разработки `http://localhost:8000/auth/google/callback`).
5. Если ключей нет — кнопка остаётся неактивной с подписью «скоро».

Старые аккаунты (зарегистрированные до этапа 2) считать подтверждёнными.

## Этап 3. Школы, роли и кабинет учителя

**Роли:** `admin` (главный админ, полный доступ), `teacher` (админ школы), `user` (ученик).
`manage_admin.py` дополнить: назначить учителя школы.

**Школы.**
1. Таблица школ: город + номер (или название). Одна школа = одна строка, без дубликатов.
2. При регистрации и в профиле ученик выбирает «без школы» или вписывает город и номер школы.
   Если такой школы нет — она создаётся.
3. Ученик попадает в школу со статусом «ожидает подтверждения»; учитель школы подтверждает
   или отклоняет. Пока не подтверждён — учитель не видит его результатов.
4. Ученик может выйти из школы или сменить её (снова нужно подтверждение).

**Кабинет учителя** (`/teacher`, доступ только `teacher` своей школы и `admin`):
1. Список учеников: последний вход, число пробных ЕНТ и тренировок, средний и лучший балл.
2. Карточка ученика: история попыток, баллы по предметам, слабые предметы (где процент
   верных ответов ниже всего), рост результата по датам.
3. **Задания:** учитель создаёт задание для всех учеников школы или выбранных —
   «N пробных ЕНТ (пара предметов по выбору или конкретная)» или «N тренировок по предмету»,
   со сроком. Засчитываются только попытки, **завершённые после выдачи задания и до срока**.
   Таблица: кто выполнил, кто нет, баллы. Ученик видит свои задания в кабинете.
4. Учитель видит только свою школу — проверять это в каждом запросе (как `user_id` сейчас).

## Этап 4. Вопросы от учителей с проверкой

1. Учитель добавляет вопросы через ту же форму, что и в админке (валидация `question_bank.py`).
2. Новый вопрос учителя получает статус «на проверке» и не попадает в тесты.
3. Главный админ видит очередь проверки: одобрить (вопрос доступен всем школам),
   отклонить с комментарием или исправить и одобрить.
4. Учитель видит статус своих вопросов и комментарии.
5. В `random_questions` и всех выборках банка брать только одобренные вопросы.

## Этап 5. Сверка вопросов со спецификацией НЦТ

1. По официальной спецификации теста ЕНТ (сайт testcenter.kz) составить для каждого предмета
   список тем с долей заданий.
2. Пометить шаблоны генераторов и вопросы темами; добавить недостающие темы.
3. В карточке ученика показывать слабые темы, а не только предметы.
   Вопросы с чужих сайтов и из сборников не копировать (авторские права) — только свои.

## Этап 6. Выкладка в интернет и монетизация

1. Сервер (VPS), автозапуск сайта и бота (systemd), домен, HTTPS, резервные копии SQLite.
2. Сайт бесплатный. Платная часть — не дороже 500 тенге (что именно платное — решить позже).
3. Реклама без JavaScript: свои баннеры (картинка + ссылка), управление из админки
   (загрузить картинку, ссылка, места показа, даты). Сервисы вроде AdSense требуют
   JavaScript и не подходят.
